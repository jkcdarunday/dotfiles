# AGENTS.md — Neovim Configuration Guide

This file provides architectural context, conventions, and operational guidelines for AI coding agents modifying or maintaining this Neovim configuration repository (`~/.config/nvim`).

---

## 1. Repository Overview

This repository is a modular, Lua-centric Neovim configuration built on:
- **Neovim Version**: Modern Neovim (v0.10+ / LuaJIT).
- **Entry Point**: `init.vim` sourcing initial runtime paths, `impatient`, `plugins`, and `lua/init.lua`.
- **Plugin Manager**: [`packer.nvim`](https://github.com/wbthomason/packer.nvim).
- **Language Server & Completion**: [`coc.nvim`](https://github.com/neoclide/coc.nvim) (Conquer of Completion) with language extensions and `coc-settings.json`.
- **Keybinding Helper**: [`vimpeccable`](https://github.com/svermeulen/vimpeccable) (`vimp`) alongside Neovim's native Lua API.
- **Theme & Aesthetics**: `material.nvim` (`darker` theme / `stealth` lualine), `lualine.nvim`, `bufferline.nvim`, `noice.nvim`, `nvim-notify`, `alpha-nvim`.

## 3. Core Architectural Principles & Conventions

### 3.1 Completion & LSP: CoC.nvim
- **Do NOT introduce native `nvim-lspconfig` or enable `mason.nvim`** unless explicitly requested by the user.
- This configuration is deliberately built around **`coc.nvim`**.
- Global extensions are managed in `lua/plugins/coc.lua` via `vim.g.coc_global_extensions`.
- Language servers not covered by extensions (e.g. `terraform-ls`) are configured in `coc-settings.json` under `"languageserver"`.
- Tab completion and Copilot interaction are handled via `copilot-workaround.vim` to coordinate suggestion acceptance and the CoC popup menu (`coc#pum#visible()`).

### 3.2 Keymapping Conventions
- **Leader Key**: Set to `<Space>` (`vim.g.mapleader = " "` in `lua/core/general.lua`).
- **Vimpeccable (`vimp`) Usage**:
  - The repository uses `vimp` (`vimp.nnoremap`, `vimp.inoremap`, `vimp.imap`, etc.).
  - **Important**: To avoid `E227: Mapping already exists` when modifying or creating mappings through `vimp`, pass the `'override'` flag when overriding existing maps:
    ```lua
    vimp.nmap({'silent', 'override'}, '<C-s>', ':w<CR>')
    ```
  - Alternatively, Neovim's standard `vim.keymap.set(mode, lhs, rhs, opts)` may be used for new native keymaps.
- **Blackhole Register Convention**:
  - Regular delete and cut keys (`d`, `D`, `x`, `X` in normal and visual modes) are mapped to the blackhole register `"_` to prevent clobbering the unnamed clipboard register.
  - To delete and copy to the system clipboard, use `<leader>d` or `<leader>D`.
- **Insert Mode Escape**:
  - `kj` and `jj` escape insert mode (`timeoutlen = 500`).
- **File & Search Navigation**:
  - `<C-P>`: Find files via `fzf-lua`.
  - `<C-\>`: Reveal Neo-tree (`:Neotree reveal<CR>`).
  - `<leader>ff`: Telescope find files.
  - `<leader>fg`: Telescope live grep.
  - `<F4>` / `<leader>tt`: Toggle terminal (`toggleterm`).

### 3.3 Indentation & Formatting
- Indentation: 4 spaces (`tabstop=4`, `shiftwidth=4`, `expandtab=true`).
- Formatting is mapped to `<M-L>` (Alt+Shift+L) via CoC (`<Plug>(coc-format)` and `<Plug>(coc-format-selected)`).

## 4. Development Workflows & Agent Instructions

### 4.1 Adding a New Plugin
1. Open `lua/plugins.lua` and add the plugin specification to `packer.startup`:
   ```lua
   use { 'author/plugin-name' }
   ```
2. If configuration is needed, create `lua/plugins/<plugin-name>.lua`.
3. Require the new module in `lua/init.lua`:
   ```lua
   require('plugins/<plugin-name>')
   ```
4. **Never manually edit `plugin/packer_compiled.lua`**. This file is compiled by Packer runtime commands (`:PackerCompile` / `:PackerSync`).

### 4.2 Removing or Disabling a Plugin
1. Comment out or remove the `require('plugins/<plugin-name>')` call in `lua/init.lua`.
2. Comment out or remove the plugin declaration in `lua/plugins.lua`.
3. If necessary, delete or rename `lua/plugins/<plugin-name>.lua`.

### 4.3 Validating Changes
After editing any Lua or Vimscript configuration files, always run a headless validation to ensure no syntax errors or breaking exceptions are introduced on startup:

```bash
nvim --headless "+quit"
```

If the command exits with exit code `0` and without unexpected lua stack traces, the core configuration loaded successfully.

## 5. Important Caveats & Gotchas

1. **`packer_compiled.lua`**:
   - Committing changes directly to `plugin/packer_compiled.lua` is discouraged. Always modify `lua/plugins.lua` instead.
2. **`init.vim.bak`**:
   - Keep this file untouched as a reference for historical Vimscript settings.
3. **Copilot Integration**:
   - `vim.g.copilot_enabled` defaults to `false` in `lua/core/general.lua`.
   - Keybindings for Copilot are managed in `copilot-workaround.vim` and `lua/core/bindings.lua`. Do not re-map `<Tab>` in insert mode without accounting for `copilot-workaround.vim`.
4. **Disabling Builtin LSP Conflict**:
   - Do not enable `vim.lsp.start` or native LSP plugins without coordinating with CoC extensions; running both will cause duplicate diagnostic markers and completion conflict.
